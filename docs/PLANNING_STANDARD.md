# Planning Standard

## Required Plan

Use a plan when requirements are ambiguous, risky, architectural, cross-object, security-sensitive, or deployment-impacting.

Include:

- Current understanding
- Evidence found
- Missing information
- Affected components
- Recommended solution
- Alternatives
- Risks
- Files likely to change
- Testing strategy
- Rollback plan

## Approval Gate

Wait for approval when the user asks for plan mode, when changes are high risk, or when business intent is unclear.

Implementation can proceed immediately when the user clearly asks to make the change and the change is low risk.
